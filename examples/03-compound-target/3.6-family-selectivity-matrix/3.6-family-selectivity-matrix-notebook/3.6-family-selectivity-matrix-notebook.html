How to run¶

Keep the notebook in its folder, which holds everything it needs: requirements.txt (mcp-bindingdb at its commit and the versions of the packages it needs), the recorded results in data/ and the figures in figures/. With uv, from that folder (replace the path with yours):

cd /path/to/3.6-family-selectivity-matrix-notebook
uv run --no-project --with-requirements requirements.txt --with jupyterlab jupyter lab 3.6-family-selectivity-matrix-notebook.ipynb

then choose Run → Run All Cells. The first start installs the packages, which takes a minute or two; the cells show the recorded results, so no database is needed. Without uv: pip install -r requirements.txt jupyterlab, then jupyter lab 3.6-family-selectivity-matrix-notebook.ipynb in the folder.

How to rerun the calls¶

To rerun every BindingDB call on your own copy of release 202610 and check each result against the recorded one, set RERUN = True in the setup cell and run all cells, or rerun the notebook without opening Jupyter, writing a copy with the new results:

cd /path/to/3.6-family-selectivity-matrix-notebook
BINDINGDB_RERUN=1 uv run --no-project --with-requirements requirements.txt --with nbconvert jupyter nbconvert --to notebook --execute --output 3.6-family-selectivity-matrix-notebook-rerun.ipynb 3.6-family-selectivity-matrix-notebook.ipynb

A rerun needs the database: the one BINDINGDB_DUCKDB=/path/to/bindingdb_202610.duckdb names (put it before uv run), else the newest one mcp-bindingdb built on this computer, for example for Claude Desktop. With neither, the first rerun builds one, which takes about half an hour and 2.4 GB. To build exactly release 202610, with a clone of mcp-bindingdb:

git clone https://github.com/pwrose/mcp-bindingdb.git
cd mcp-bindingdb
git checkout 4fad6d8e47a12cf81a3d235a82a744752ac14376
scripts/build_duckdb.sh --release 202610

The setup cell checks the database's release and source checksum against the recorded ones.

Run as it is, each call cell shows its recorded result, read from data/ and checked against the SHA-256 digest recorded in the cell. Rerun, it shows the new result with ✅ when it matches the recorded one (floats to 10 significant digits, ids of viewers and files left out). Calls to PubChem, RCSB or PDBe depend on those services and may differ. The prose answers are the model's and are not recomputed.

🧠 Assistant

Requiring all four measurements keeps the series and drops the outlier.

With require_all_targets, 1,456 compounds qualify and the top six are the same series as before — BDBM50031738 is the only compound to fall out of the leading group, which is the one whose JAK2 datapoint was a > bound.

The structures show why the ranking is so flat across the six: they differ only in the group on the aminopyrimidine's aryl ring (methyl ester, oxazole, benzothiazole, ethyl ester, glycolate), while the indole and the methoxy-methylpiperazinyl-propanamide are constant. Selectivity moves between 1,413× and 2,754× across that whole set, so none of those substituents is what buys JAK1 selectivity; the shared core is.

For a JAK1-selective starting point this series is the obvious anchor, with the caveat that its selectivity over JAK2 — the only family member it actually binds — is about 3 log units and no better.
