👤 User

Give me the SMILES and the BindingDB record for three compounds I only know by name: the trade name Ibrance, the IUPAC name N-(3-chloro-4-fluorophenyl)-7-methoxy-6-(3-morpholin-4-ylpropoxy)quinazolin-4-amine, and the CAS number 50-78-2.

How the lookup works. The tool tries three sources in order and stops at the first one that knows the name:

  1. BindingDB synonyms: trade names, common names, ChEMBL ids and patent labels already in the database. "Ibrance" is a BindingDB synonym of palbociclib.
  2. OPSIN: a parser that turns systematic IUPAC names into structures. It runs offline and needs no database. BindingDB did not know the IUPAC string as written, but OPSIN built the structure from the name itself.
  3. PubChem: name lookup on the web, which also handles CAS numbers. 50-78-2 is aspirin (PubChem CID 2244).

When a structure comes from OPSIN or PubChem, the tool matches it back to BindingDB by InChIKey. For gefitinib it found three records with the same InChIKey: BDBM5447 ("Iressa", 1,177 measurements), BDBM50338602 (6 measurements) and BDBM32367 (no measurements). Use the record with the data. Aspirin's record happens to be named "Zorprin", a brand name, which shows why matching by structure is more reliable than matching by name.

The lesson: resolve names to structures first. Most of the powerful searches (similarity, substructure, exact structure) take a SMILES string, not a name. Converting a name to a SMILES string is usually the first step of a structure-based analysis. Watch for one pitfall: a generic label such as "compound 5" can belong to many BindingDB compounds from different papers. The tool then returns all candidates and sets ambiguous=true, and you should pick one by checking the structures.
