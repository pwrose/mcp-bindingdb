👤 User

I have a few identifiers for the same drug: CHEMBL941, PubChem CID 5291, BDBM13530 and the InChIKey block KTUFNOKKBVMGRW. Do they all find the same compound in BindingDB?

🧠 Assistant

Yes. All four identifiers lead to imatinib (BDBM13530), the record with 1,156 measurements against 459 targets. The InChIKey search also turns up three more BindingDB records for the same molecule, which the other identifiers miss.

Query Type Top hit Notes
CHEMBL941 ChEMBL id BDBM13530 Exact match ranks first. Further rows are substring matches (CHEMBL94191, CHEMBL9416 ...) and should be ignored
cid_5291 PubChem CID BDBM13530 BindingDB stores PubChem CIDs as cid_<number>; again, substring matches (cid_5291664 ...) follow
BDBM13530 BindingDB id BDBM13530 Only one hit
KTUFNOKKBVMGRW InChIKey first block 5 records See below

What the InChIKey search adds. An InChIKey has three blocks. The first 14 characters encode the molecular skeleton (atoms and connectivity). The second block encodes stereochemistry and isotopes, and the last character encodes protonation. Searching on the first block alone finds every record built on the same skeleton:

The lesson: one molecule can have several BindingDB records. BindingDB creates records as data are deposited from different papers and patents. BDBM86734 has the identical full InChIKey as BDBM13530 and carries 66 more imatinib measurements. A search on the name or ChEMBL id never shows it. The two deuterated records (second block BMSJAHLVSA) are isotope-labelled imatinib, which is a different substance and usually should not be pooled.

If you want all data for a compound, search by the full InChIKey (same molecule, same isotopes and stereo) or by the first block (all stereoisomers, isotopologues and charge states), then decide which records to merge. Tools such as find_targets_for_compound accept an inchi_key argument for this.

How this was answered

  1. search_compounds four times, once per identifier. The same tool accepts names, ChEMBL ids, PubChem cid_N, BDBM ids and full or partial InChIKeys.
  2. run_sql to count measurements and targets for every record whose InChIKey starts with KTUFNOKKBVMGRW-.
