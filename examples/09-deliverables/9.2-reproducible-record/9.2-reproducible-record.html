Abemaciclib binds CDK9 only about 30-fold more weakly than CDK4, and CDK1 and CDK2 about 160- to 190-fold more weakly. Palbociclib and ribociclib keep a window of roughly three orders of magnitude over CDK2 and CDK9 (palbociclib ~75× over CDK9), and are essentially inactive on CDK1, CDK5 and CDK7. Ribociclib's CDK2 value rests on just two exact measurements (7 more are "> value"), so its 7,600× window is the least certain number in the table. Because "> value" results are left out of the medians, the medians for the weak targets are if anything too potent: palbociclib also has 10 censored results on CDK2 besides its 14 exact ones.

The lesson: a reproducible record shows the choices, not just the answer. The tool calls below contain the exact SQL, so a reader can see every decision behind the table:

  • Which records count as "CDK1", "CDK2", ... BindingDB names CDK targets in many ways: "Cyclin-dependent kinase 6/G1/S-specific cyclin-D3", "CDK6/cyclin D1", "Cyclin-A2/Cyclin-dependent kinase 2", and even "Cyclin-dependent kinase/G2/mitotic-specific cyclin- 1", which is the CDK1/cyclin B1 complex. A pattern on the target name misses that last record, which holds 9 of abemaciclib's 17 exact CDK1 values, and would count the mixed record "Cyclin-dependent kinase 4/6" as CDK4. So the query takes the CDK from the target's protein chains instead: a chain counts as CDKn when one of its BindingDB names is exactly "CDKn", and records with two different CDKs are skipped. The second query lists every record assigned to each CDK, with exact and censored counts per drug, so the assignment can be checked line by line.
  • Pooling. Plain kinases and CDK/cyclin complexes are pooled, and mutant records (names with "[...]") are excluded.
  • Which values. Only exact ('=') Ki, Kd and IC50 values are used; EC50 values (often cell-based) are left out. Censored values such as "> 10 µM" are excluded (see Example 8.4).

A colleague who disagrees with any of these choices can change one line of SQL and rerun it. A results table on its own does not allow that. The choices matter here: the CDK1 column for abemaciclib (372 nM from 17 values) would read 56 nM from 9 values with a name pattern that misses the CDK1/cyclin B1 record.

  • search_compounds for ribociclib, abemaciclib and palbociclib to get their BindingDB ids (BDBM148264, BDBM50110183 and BDBM6309).
  • run_sql: listed the kinase target names measured for the three drugs, to see how BindingDB names the CDK records.
  • run_sql: median pAffinity per drug and CDK, as described above.
  • run_sql: the target records counted as each CDK, with exact and censored counts per drug.
  • run_sql: the same medians with a name pattern on the target name instead (CDK number taken from "cyclin-dependent kinase n" or "CDKn", all exact values), for comparison: it gives abemaciclib 56 nM on CDK1 (n=9) and pools 43 values as CDK4.
  • create_transcript with include_tool_calls=true, listing only the calls that belong to this analysis. The server logs every BindingDB call it runs, with its arguments and full result.

How to make your own reproducible record. Ask for it in plain words: "include the tool calls", "with the queries and results", or "a reproducible record". It is cleanest to start the analysis with a fresh log ("reset the tool log first"). Otherwise the assistant picks your calls out of the shared log by index. Exploratory calls (here, two lookups of the components of the oddly named complexes) are left out, so the record shows the path to the answer, not every detour.

Call 5 — run_sql

2026-11-24T04:56:36+00:00

-- How selective are the three approved CDK4/6 drugs within the CDK family?
-- BindingDB names CDK records many ways ('Cyclin-dependent kinase 6', 'CDK6/cyclin D1',
-- 'Cyclin-A2/Cyclin-dependent kinase 2', 'Cyclin-dependent kinase/G2/mitotic-specific cyclin- 1', ...),
-- so the CDK is taken from the target's protein chains instead of its name: a chain counts as CDK<n>
-- when one of its BindingDB names is exactly 'CDK<n>'. Plain kinases and CDK/cyclin complexes are pooled;
-- records with two different CDKs (the mixed 'Cyclin-dependent kinase 4/6') and mutant records ('[...]')
-- are skipped; exact values only; median pAffinity per drug and CDK.
WITH chain AS (            -- every protein chain of each target: the polymer itself, or a complex's components
  SELECT polymerid AS chain_id, polymerid, NULL::BIGINT AS complexid FROM polymer
  UNION ALL
  SELECT polymerid, NULL, complexid FROM complex_component WHERE polymerid IS NOT NULL
),
cdk_chain AS (             -- chains that are a CDK, with its number
  SELECT DISTINCT polymerid AS chain_id, regexp_extract(name, '^CDK(\d+)$', 1) AS cdk
  FROM poly_name WHERE regexp_matches(name, '^CDK\d+$')
),
target_cdk AS (            -- each target with its single CDK
  SELECT c.polymerid, c.complexid, min(k.cdk) AS cdk
  FROM chain c JOIN cdk_chain k USING (chain_id)
  GROUP BY c.polymerid, c.complexid
  HAVING count(DISTINCT k.cdk) = 1
),
m AS (
  SELECT CASE a.monomerid WHEN 6309 THEN 'Palbociclib' WHEN 148264 THEN 'Ribociclib' ELSE 'Abemaciclib' END AS drug,
         t.cdk, a.p_affinity
  FROM activity a
  JOIN target_cdk t ON (a.polymerid = t.polymerid OR a.complexid = t.complexid)
  WHERE a.monomerid IN (6309, 148264, 50110183)   -- palbociclib, ribociclib, abemaciclib
    AND a.affinity_type IN ('Ki', 'Kd', 'IC50')
    AND a.relation = '='
    AND a.target_name NOT LIKE '%[%'
)
SELECT drug, 'CDK' || cdk AS kinase, count(*) AS n,
       round(median(p_affinity), 2) AS median_p,
       round(1e9 * power(10, -median(p_affinity))) AS median_nM
FROM m
GROUP BY ALL
HAVING count(*) >= 2
ORDER BY drug, median_p DESC, kinase

WITH m AS (
  SELECT c.name AS drug,
         coalesce(nullif(regexp_extract(a.target_name, '(?i)cyclin-dependent kinase (\d+)', 1), ''),
                  nullif(regexp_extract(a.target_name, '^CDK(\d+)', 1), '')) AS cdk,
         a.p_affinity
  FROM activity a JOIN compound c USING (monomerid)
  WHERE a.monomerid IN (6309, 148264, 50110183)
    AND a.relation = '='
    AND (a.target_name ILIKE '%cyclin-dependent kinase %' OR a.target_name LIKE 'CDK%')
    AND a.target_name NOT LIKE '%[%'
)
SELECT drug, 'CDK' || cdk AS kinase, count(*) AS n,
       round(median(p_affinity), 2) AS median_p,
       round(1e9 * power(10, -median(p_affinity))) AS median_nM
FROM m
WHERE cdk IS NOT NULL
GROUP BY ALL
HAVING count(*) >= 2
ORDER BY drug, median_p DESC
