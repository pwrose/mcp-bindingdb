👤 User

What tables are in the BindingDB database, and which ones should I start with?

🧠 Assistant

The database has 36 tables. Start with the five derived tables. They were built from the raw BindingDB tables to make queries easy: values are parsed into numbers with explicit units, and compound, target and citation details are copied onto every measurement row.

Start here (derived tables)

Table Rows One row per
activity 3,248,380 measurement (Ki, Kd, IC50, EC50, kon, koff) with its compound, target, assay and citation
compound 1,475,994 small molecule: name, InChIKey, SMILES, molecular weight, counts
compound_name 2,549,453 compound synonym (names, ChEMBL ids, PubChem cid_N, patent labels)
target 13,415 target (protein or complex): UniProt, organism, counts
target_name 78,247 target synonym (gene names, UniProt entry names)

Raw tables you may need later. These mirror BindingDB's own MySQL schema:

Table Rows Use it for
article 57,276 publications and patents: PubMed id or patent number, DOI, title, year
assay 233,365 full assay names and descriptions
entry 57,295 deposition records: title, measurement technique, date
polymer / complex / complex_component 12,157 / 1,260 / 3,252 protein sequences and PDB ids; multi-subunit targets and their parts
monomer 1,475,994 raw compound records, including the PDB ligand ids
ki_result / enzyme_reactant_set 3,243,658 / 3,243,679 the raw measurements (values stored as text) and the compound-to-target links
itc_result_a_b_ab 1,822 isothermal titration calorimetry: ΔG, ΔH, ΔS, stoichiometry
pdb_bdb 184,496 PDB entry to BindingDB id mappings

The remaining tables describe experimental conditions (buffers, solvents, instruments, data-fitting methods) and keywords.

The activity table, column by column (27 columns):

  • The measurement: affinity_type, relation ('=', '<', '>'), value and unit (nM), p_affinity (-log10 molar), raw_value (the text as deposited), uncertainty, ph, temp_k
  • The compound: monomerid, compound_name, inchi_key
  • The target: polymerid or complexid, target_name, uniprot, uniprot_raw (with mutations and residue ranges), organism, taxid
  • Where it came from: assay_name, entryid, articleid, source_id (PubMed id or patent number), doi, year
  • Internal keys: ki_result_id, reactant_set_id

A lesson about derived vs raw tables. In the raw ki_result table an affinity is stored as text, such as ">10000", with the unit implied. In activity the same value is split into relation, a numeric value in nM and a p_affinity. That split is what makes median(p_affinity) or WHERE value <= 100 possible. Use the raw tables only when you need something the derived ones leave out, such as ITC thermodynamics (Example 7.5) or PDB mappings (Example 7.6).

How this was answered

  1. describe_tables with no argument lists every table with its description and approximate row count.
  2. describe_tables with table='activity' lists that table's columns and types, plus a few sample rows.

describe_tables only reads the schema, so it isn't recorded as a tool call. Use it before writing any run_sql query.
