Abemaciclib binds CDK1 and CDK9 only about 30-fold more weakly than CDK4. Palbociclib and ribociclib keep a window of two to three orders of magnitude. Ribociclib's CDK2 value rests on just two measurements, so its 7,600× window is the least certain number in the table.

The lesson: a reproducible record shows the choices, not just the answer. The tool calls below contain the exact SQL, so a reader can see every decision behind the table:

  • Which records count as "CDK4". BindingDB names CDK targets two ways, "Cyclin-dependent kinase 6/G1/S-specific cyclin-D3" and "CDK6/cyclin D1". A first version of this query matched only the long form and silently dropped palbociclib's best CDK6 data (the CDK6/cyclin D1 complex, 12 measurements). The version shown matches both forms.
  • Pooling. Plain kinases and CDK/cyclin complexes are pooled, and mutant records are excluded.
  • Which values. Only exact ('=') values are used. Censored values such as "> 10 µM" are excluded (see Example 7.4).

A colleague who disagrees with any of these choices can change one line of SQL and rerun it. A results table on its own does not allow that.

How this was answered

  1. search_compounds for ribociclib and abemaciclib to get their BindingDB ids. Palbociclib is BDBM6309 (Example 1.4).
  2. run_sql: median pAffinity per drug and CDK, as described above.
  3. create_transcript with include_tool_calls=true, listing only the calls that belong to this analysis. The server logs every BindingDB call it runs, with its arguments and full result.

How to make your own reproducible record. Ask for it in plain words: "include the tool calls", "with the queries and results", or "a reproducible record". It is cleanest to start the analysis with a fresh log ("reset the tool log first"). Otherwise the assistant picks your calls out of the shared log by index. Exploratory or failed calls are left out, so the record shows the path to the answer, not every detour.

2026-10-25T07:21:57+00:00

-- How selective are the three approved CDK4/6 drugs within the CDK family?
-- BindingDB names CDK records two ways: 'Cyclin-dependent kinase 6/...' and 'CDK6/cyclin D1',
-- so extract the CDK number from either. Plain kinases and CDK/cyclin complexes are pooled;
-- mutant records ('[...]') are skipped; exact values only; median pAffinity per drug and CDK.
WITH m AS (
  SELECT c.name AS drug,
         coalesce(nullif(regexp_extract(a.target_name, '(?i)cyclin-dependent kinase (\d+)', 1), ''),
                  nullif(regexp_extract(a.target_name, '^CDK(\d+)', 1), '')) AS cdk,
         a.p_affinity
  FROM activity a JOIN compound c USING (monomerid)
  WHERE a.monomerid IN (6309, 148264, 50110183)   -- palbociclib, ribociclib, abemaciclib
    AND a.relation = '='
    AND (a.target_name ILIKE '%cyclin-dependent kinase %' OR a.target_name LIKE 'CDK%')
    AND a.target_name NOT LIKE '%[%'
)
SELECT drug, 'CDK' || cdk AS kinase, count(*) AS n,
       round(median(p_affinity), 2) AS median_p,
       round(1e9 * power(10, -median(p_affinity))) AS median_nM
FROM m
WHERE cdk IS NOT NULL
GROUP BY ALL
HAVING count(*) >= 2
ORDER BY drug, median_p DESC
